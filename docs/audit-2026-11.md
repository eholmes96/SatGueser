# SatGueser codebase audit (November 2026)

## How this was done

1. **Safety net first.** The project had no tests, so a permanent suite was added before anything was rewritten:
   - **Unit tests** (`npm test`): 84 tests on scoring, the Daily draw, dates and storage, the geo arrows, autocomplete and the datasets, plus the Daily server function with Supabase mocked.
   - **Golden files:** the Daily picks for every date to mid-2027, and autocomplete results for fixed queries.
   - **Browser tests** (`npm run test:e2e`): a full game in all 5 modes, on a controlled clock. Every score, timer drop, hint, Time's Up and scorecard value is checked exactly.

   Every test passed against the code as it was.
2. **Audit.** Six Opus 5.5 reviewers each read one section, without editing anything:
   - game engine;
   - app shell;
   - UI components;
   - backend & privacy;
   - data & lookups;
   - dev sandbox, blog & tooling.

   Between them they reported 76 findings. Every high and medium finding was then checked against the code before being accepted. Some were reproduced in a browser, a Node script or a local Postgres. Duplicates across sections were merged.
3. **Rewrites.** Fixes that change nothing a player sees or the server stores were applied by Sonnet 5.5 agents, in batches with no overlapping files. Every diff was then reviewed and the full suite re-run.
4. **Held for your OK.** Anything that changes what players see, what's stored, or the database is listed in sections 1 and 2 instead of being applied.

**IDs:** the prefixes are ENG (engine), APP (app shell), UI (components), BE (backend), DATA (data), DEV/BLOG/DEP/TOOL/DOCS (sandbox, blog, dependencies, tooling, docs). Where reviewers overlapped, the IDs are combined, e.g. "UI-1 / APP-2".

## 1. Bug fixes held for your OK (recommended)

These are real bugs, and the fixes only make things better. Players will notice a difference, though, which is why they're held. You can approve them as a group.

### Most important

| ID | What happens today | Proposed fix |
|---|---|---|
| **DATA-1** (verified) | **Daily rejects the right answer.** The Daily suggestion list offers both "New York" and "New York, USA", but only the first counts as correct. Picking the ", USA" version costs 100 × the multiplier (−300 on the hard slot) for naming the right city. 9 cities have a ", USA" twin, and 29 of the first 180 days include one. | Drop the 9 ", USA" twins from the Daily suggestion list. They're never Daily answers. |
| **UI-1 / APP-2** (verified) | **A debug box can show the answer.** Any map error, including ones the code itself calls harmless, switches on a "temporary diagnostics" overlay. It shows the round's city name and coordinates for the rest of the session, plus a red error box over the × button. | Remove the overlay for players (keep it behind `?debug` for you), and don't report harmless errors. |
| **UI-2** (verified) | **Autocomplete opens off the bottom of the screen.** On phones only the first of up to 8 suggestions is visible, and on desktop most rows are below the edge. | Open the list upwards, above the input. |
| **APP-1** (verified) | **Light-mode headings are nearly invisible.** If the phone or computer is in light mode, the "Stats" and blog titles come out near-black on the dark background. The page also flashes white while loading. This is a leftover from the Vite starter template's CSS. | Make the base styles dark-only, and add a `theme-color` meta tag. |
| **UI-4** (verified) | **Missing WebGL or token blanks the page.** If the map can't start (no WebGL, or a missing token), the whole page goes blank, including the blog and the account bubble. | Catch the error and show an explanation card. Optionally add an error boundary. |
| **ENG-5** | **A full or blocked browser storage blanks the page at Daily game-over.** Saving the result throws, and the run is never sent to the server. | Catch the storage error and still show the result and submit the run. |
| **ENG-6** | **The round clock can leak into the next round.** A correct guess in the half-second before the clock starts, or exiting before the map loads, leaves a timer running. The next round's bar then moves early and can score lower. | Stop the clock on every transition, and only start it for a live round. |

## 2. Design decisions for you

| ID | Topic | Notes |
|---|---|---|
| DATA-2, DATA-3 | **Smarter autocomplete.** Typing past the city name returns nothing for airports ("chicago o"). Punctuation and "St."/"Saint" also break matching: "st louis", "washington d" and "winston salem" all return nothing. | The fix makes more queries match. Existing rankings are unchanged. |
| BE-2 | **One Daily per day, across devices.** A signed-in player can replay the Daily on a second device. The server keeps the first score, but shows the second. | Needs a small database migration, and a server check before a signed-in player starts. |
| BE-3 | **Limits on stored game results.** Any account can insert huge or fake rows into `game_results`, inflating its own personal best or filling the database. Default table permissions are also wider than needed. | Database migration: size and score checks, and tighter grants. |
| BE-6, UI-8 | **Database performance and Stats accuracy.** The Stats page downloads every game row, and becomes silently wrong after 1,000 games (Supabase's row cap). Some indexes are redundant or missing. | Migration: an aggregate view, new indexes, and the RLS `auth.uid()` wrapper that the Supabase advisor recommends. |
| BE-8 | **Security headers.** There's no Content-Security-Policy or `nosniff` header. An unknown `/api/...` path returns the game page with a 200. | Add a `headers` block to `vercel.json`, starting in report-only mode. |
| APP-9, DEV-1, BLOG-1, DATA-6 | **Smaller download.** `/dev`, the blog and the Markdown library load for every player (about 20–25 KB gzipped). Mapbox isn't in its own cached chunk. | Lazy-load `/dev` and the blog (a brief blank screen on first open), render Markdown at build time, and split Mapbox out. |
| UI-6, UI-11, APP-10 | **Accessibility.** The autocomplete has no screen-reader support. The dialogs don't manage focus. There's no reduced-motion support. | A dedicated accessibility pass. |
| BLOG-3 | **Blog SEO.** Shared blog links preview as the game card. There's no sitemap and no canonical URLs. | Pre-render blog pages at build time. |
| DEV-1 | **Reset button in `/dev`.** It wipes a guest's streak without asking. | Add a confirmation. |

## 3. Fixed in this pass (no visible change)

### Game engine
- **ENG-1:** `submitGuess` now decides whether a guess was right before updating state. React sometimes runs state updates late, so it used to report every correct guess as wrong. Players never saw it, because the round ended first, but it queued a bogus distance hint and a shake on each correct guess.
- **ENG-8:** `scoreRound` now rejects bad inputs. A non-number time counts as a timeout, and a negative wrong-guess count counts as 0, so it can no longer return 1,300 or `NaN`.
- **ENG-9:** the Daily draw's cache is now kept per dataset, so results depend only on the dataset and the date.
- **ENG-10:** the Eastern date key is built from date parts, instead of relying on the `en-CA` locale's formatting.
- **ENG-11:** saved Daily records and high scores are validated on load. Corrupt data falls back to empty instead of crashing the recap card.
- **ENG-12:** stale comments are fixed ("Edge Function", "Deno", "four modes", and others). The duplicated round-results mapping is now one helper.

### UI and app shell
- **UI-12 / APP-6:** the game-over and Daily recap rows now share one `ScoreBreakdown` component. There's also a shared `DifficultyBadge` and shared button styles, so a column change happens in one place. The two cards' existing differences are kept as-is. Showing ×N in the recap would be a visible change, so it was left for your call.
- **APP-8:** the map and the guess input no longer re-render on every 200 ms timer tick.
- **UI-13, APP-11 (partly), APP-12:**
  - dead props removed (`onAnimationComplete`, and the input's `disabled`/`phase`);
  - the autocomplete pool is a per-mode lookup, so a new mode can't silently fall back to US cities;
  - the round length is no longer hard-coded as 30000;
  - the empty `App.css` and the unused template CSS are gone.
- **DEV-2:** the sandbox imports the game's zoom and round-length constants instead of keeping its own copies.

### Tooling, dependencies, blog, docs
- **DEP-1 (important):** `esbuild` is now declared. The API build used it, but it was only installed as an optional extra of Vite, a leftover from removing `@vercel/node` in October. A regenerated lockfile could have broken every Vercel deploy.
- **DEP-2:** Vite went from 8.1.0 to 8.3.8, fixing Vite's own dev-server advisories (argument injection, a file-serving bypass). `@types/mapbox-gl` is removed; it was a deprecated stub, and `mapbox-gl` ships its own types.
  - `npm audit --omit=dev` (what ships) reports 0.
  - The remaining dev-only findings are one `picomatch` ReDoS with no fixed release yet. It's counted six times through vite, vitest and others.
  - There's also a low, Windows-dev-server-only esbuild advisory, inside `tsx`'s private copy. `tsx` is an optional Vite extra the project doesn't use.
- **TOOL-1:** `npm run build` now also type-checks the server function (`tsconfig.api.json`). A new `npm run check:api` fails if the committed `api/` bundle is stale.
- **TOOL-3:** `.gitignore` no longer matches the tracked `.env.example`, and now ignores test reports and local Claude settings. Lint skips the generated `api/` bundle.
- **DEAD-1:** removed the unused `src/cities.json` (an old dataset with 17 stale difficulties), the template images and `public/icons.svg`.
- **BLOG-4 / BLOG-5:**
  - Blog Markdown now escapes raw HTML and drops `javascript:`/`data:` links.
  - The frontmatter parser handles BOMs, CRLF line endings and quotes.
  - Content mistakes (a missing title, a bad date, a duplicate slug) now fail a unit test rather than crashing the site.
  - The rendered HTML of the existing posts is byte-identical.
- **Docs:**
  - README and CLAUDE.md: real dataset counts, Airports added, leaderboards described as locked, all scripts listed, and guidance on URL-restricting the Mapbox token.
  - Stale code comments are fixed across `src/lib`, the server function and the utilities.

### How it was verified
- **Tests:** 95 unit tests and 10 browser tests pass. The Daily golden file (every date to mid-2027) is unchanged, and the server-function tests pass against the regenerated bundle.
- **Old vs new, side by side:** both versions ran through the same 46 checkpoints, on desktop and phone: menus, games in three modes, suggestions, hints, result cards, game-over, the Daily recap, the blog and `/dev`. Every element's position, size, text and computed style is identical.
- **Bundle size:** on the same Vite version, the app bundle is the same size as before (+0.5 KB JS, −0.4 KB CSS). The Vite upgrade alone cut it from 2,408 KB to 2,209 KB (667 → 618 KB gzipped).
- **Server bundle:** `api/submit-daily.js` was regenerated, because `scoring.ts` and `dailyChallenge.ts` changed. esbuild 0.27.0 and 0.28.2 produce identical output.

## 4. Not acted on

- **TOOL-2:** a quieter `npm ci` in the Claude Code session-start hook. This is session config you set up, so I left it alone. It's a small suggestion for you.
- **`engines` field:** pinning Node 24 in `package.json` could change the Node version Vercel uses, so check the Vercel project setting first.
- **`noUncheckedIndexedAccess`:** a stricter TypeScript setting. It's worth turning on, but needs a pass over the code.
- **Reviewer claims that didn't hold up:**
  - TypeScript `strict` is on by default in TS 6.
  - The Daily suggestion list has no *exact* duplicate names; the real issue is the twins in DATA-1.
  - Inline style objects aren't a real cost.

## 5. Broader recommendations

1. **CI on every PR** (GitHub Actions):
   1. `npm ci`
   2. lint
   3. `tsc -b`
   4. build
   5. `npm run check:api`, which catches a stale server bundle (this happened once in September)
   6. unit tests
   7. browser tests
   8. `npm audit --omit=dev`
2. **A committed Daily schedule** (see ENG-2). Then data edits can't change past or current days.
3. **A leaderboard, done carefully.** Before re-opening the leaderboard functions:
   - let players pick a display name, since the default is the email prefix;
   - make streaks decay;
   - decide what the "Sign in to appear on the leaderboard" text should say until then.
4. **Self-service account deletion,** and a short note on what's stored.
5. **Move the game engine into a pure reducer,** with timing held in state. Bugs like ENG-1 and ENG-6 become impossible, and the engine can be tested without a browser.
6. **Dependabot** for npm, with patch and minor updates grouped.
